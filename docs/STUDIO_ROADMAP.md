# Telegram Channel Studio

## الهدف

تحويل Telegram Channel Saver إلى برنامج محلي مريح لإدارة أرشيف منشورات عدة قنوات، مع الحفاظ على اتصال المستخدم عبر MTProto و`API_ID` و`API_HASH`.

## ما أُنجز في البداية

- إضافة `src/studio_store.py` كطبقة SQLite مستقلة.
- فهرسة القنوات والمنشورات والمستخدمين من قاعدة JSON الحالية.
- البحث حسب النص، القناة، التاريخ، والوسائط.
- الاحتفاظ بمصدر JSON كما هو؛ الفهرس المحلي ليس بديلًا عن النسخة الأصلية.
- إضافة `studio.py` كأداة تشغيل أولية للفهرسة والبحث.

تشغيل مثال:

```bash
python studio.py index /path/to/database.json /path/to/studio.sqlite3
python studio.py search /path/to/studio.sqlite3 --text "كلمة" --limit 100
```

## المرحلة التالية

1. ربط واجهة تسجيل الدخول مع `src/telegram_gateway.py` دون كشف بيانات الجلسة للواجهة.
2. استخدام `src/telegram_sync.py` للمزامنة التزايدية مع تقدم وأخطاء جزئية.
3. بناء خدمة محلية للمنشورات والقنوات مع معاينة قبل التعديل.
4. إضافة خطط bulk edits وسجل عمليات قابل للتراجع.
4. إضافة واجهة سطح مكتب/ويب خفيفة فوق الخدمة.
5. إضافة الجدولة وإعادة النشر مع احترام صلاحيات Telegram وFloodWait.
6. إضافة طبقة الجمهور والإحصاءات اعتمادًا على البيانات التي يتيحها Telegram فقط.

## ترتيب التنفيذ المعتمد

يُنفذ المشروع على أربع طبقات متتابعة. تبدأ الطبقة الأولى بالفهرسة والتحليل والتدقيق
والتشابه والفلاتر. بعدها تأتي طبقة التحرير المحلي، وفيها القوالب والمحرر الطبقي
والعمليات الجاهزة والمعاينة. ثم تأتي طبقة حزم التغييرات وسجل النسخ والتراجع
والجدولة. ولا تُفعّل الكتابة على Telegram إلا بعد نجاح الطبقات السابقة واختبار
الصلاحيات والفشل الجزئي و`FloodWait`.

## حدود المنتج

عدادات المشاهدة لا تكشف أسماء المشاهدين. وقائمة المتفاعلين في منشورات القنوات قد تكون محجوبة من Telegram لمنع كشف الهوية. لذلك ستعرض التحليلات "النشاط القابل للرصد" فقط، ولن تنسب المشاهدات المجهولة إلى أفراد.

## مبدأ الأمان

تظل جلسة Telegram والبيانات محلية. لا تُرسل `API_HASH` أو ملفات الجلسة إلى خدمة خارجية، ولا تُنفذ تعديلات جماعية مباشرة دون معاينة وحزمة تغييرات وتأكيد واضح.
